# playedu-system 系统模块概要

## 模块定位

本模块负责应用启动阶段的数据库与基础数据治理，以及权限、日志、锁等横切关注点。它依赖 `playedu-common` 中的实体、Service 和注解，由可执行应用统一扫描并加载。

## 启动检查

各检查类实现 `CommandLineRunner`，通过 `@Order` 控制执行顺序：

| 类 | 主要职责 |
| --- | --- |
| `MigrationCheck` | 创建/升级核心数据库结构，并记录迁移版本 |
| `SystemDataCheck` | 初始化系统必要数据 |
| `AppConfigCheck` | 补齐和更新默认应用配置项 |
| `AdminPermissionCheck` | 补齐、更新后台权限定义 |
| `UpgradeCheck` | 执行版本升级后的配置和权限清理/修正 |

`Migration`、`MigrationMapper` 和 `MigrationService` 负责维护 `migrations` 记录。启动顺序上，迁移表和核心结构先于系统数据、配置及权限初始化；考试模块的迁移也依赖同一记录表。

## AOP 横切能力

- `BackendPermissionAspect`：拦截 `@BackendPermission`，校验当前管理员是否拥有接口要求的权限。
- `AdminLogAspect`：拦截 `@Log`，在成功或异常后记录管理员操作、业务类型、请求信息和结果。
- `LockAspect`：拦截 `@Lock`，围绕业务方法获取和释放公共锁实现。

注解本身定义在 `playedu-common`，这样业务模块只依赖公共层即可声明横切语义，具体执行逻辑由本模块集中维护。

## 代码结构

```text
src/main/java/xyz/playedu/system/
├── aspectj/       # 权限、日志和锁切面
├── checks/        # 应用启动检查与升级逻辑
├── domain/        # Migration 实体
├── mapper/        # Migration Mapper
└── service/       # 迁移记录服务
```

## 维护要点

- 启动检查会直接修改数据库和基础数据，新增逻辑必须保证幂等，并验证重复启动不会产生副作用。
- 数据库变更应使用新的唯一迁移名称，不要修改已经在生产环境执行过的迁移含义。
- 调整 `@Order` 前需确认依赖关系，尤其是迁移表、业务表、配置和权限数据的先后次序。
- 权限常量、权限初始化清单和 Controller 上的权限注解需要保持一致。
- 操作日志应避免记录密码、Token、密钥和大体积请求体。
- 当前锁底层来自公共模块的内存实现；多实例部署时需替换或扩展为真正的共享分布式锁。
