# PlayEdu 后端项目概要

## 1. 项目定位

`playedu-api` 是 PlayEdu 企业内部培训系统的 Java 后端工程，向管理后台、PC 学员端和 H5 学员端提供统一的 HTTP API。工程采用 Maven 多模块结构，将接口适配、公共基础能力、课程学习、资源管理、系统初始化和考试能力分开维护，最终由同名的 `playedu-api` 应用模块组装为一个可运行的 Spring Boot 服务。

## 2. 技术基线

| 项目 | 当前配置 |
| --- | --- |
| Java | 17 |
| Spring Boot | 3.3.4 |
| 构建工具 | Maven Wrapper / Maven 多模块 |
| Web | Spring MVC、Validation、WebSocket |
| 数据访问 | MyBatis-Plus 3.5.7、MySQL、HikariCP、部分模块使用 `JdbcTemplate` |
| 鉴权 | Sa-Token 1.39.0、JWT、Bearer Token |
| 文件存储 | AWS S3 SDK，兼容 S3/MinIO 的上传流程 |
| 其他 | Spring AOP、异步任务、定时任务、Gson、Hutool、ip2region |

默认服务端口为 `9898`，数据库名默认为 `playedu`。配置集中在 `playedu-api/src/main/resources/application.yml`，可通过环境变量覆盖数据库、连接池、Token 密钥、并发登录和演示模式等参数。

## 3. 模块结构

| 模块 | 主要职责 | 直接依赖 |
| --- | --- | --- |
| [`playedu-api`](./playedu-api/项目概要.md) | 启动入口、Controller、请求对象、拦截器、事件监听和定时任务 | 全部业务模块 |
| [`playedu-common`](./playedu-common/项目概要.md) | 用户、部门、权限、LDAP、配置、通用类型与基础设施 | 父工程公共依赖 |
| [`playedu-course`](./playedu-course/项目概要.md) | 课程、章节、课时、附件、可见范围和学习进度 | `playedu-common`、`playedu-resource` |
| [`playedu-exam`](./playedu-exam/项目概要.md) | 题库、试卷、版本、练习与判分 | `playedu-common`、Spring JDBC |
| [`playedu-resource`](./playedu-resource/项目概要.md) | 素材分类、资源元数据、视频扩展信息和上传 | `playedu-common` |
| [`playedu-system`](./playedu-system/项目概要.md) | 数据迁移、系统初始化、权限/日志/锁切面 | `playedu-common` |

依赖方向以 `playedu-common` 为基础层；`playedu-resource` 位于资源领域层；`playedu-course` 在其上关联课程与资源；`playedu-exam` 是相对独立的考试领域；可执行的 `playedu-api` 位于最外层负责聚合和暴露接口。

## 4. 运行时架构

请求进入服务后，先由 `WebMvcConfig` 注册的拦截器区分管理端与学员端，再进入 Controller。Controller 完成参数校验、上下文读取和响应封装，业务逻辑由各模块 Service 承担，最终通过 MyBatis-Plus Mapper、XML Mapper 或 `JdbcTemplate` 访问 MySQL。

接口主要分为两组：

- `/backend/v1/**`：管理端接口，覆盖管理员、角色权限、用户部门、课程、资源、上传、LDAP、题库和试卷等功能。
- `/api/v1/**`：学员端接口，覆盖登录、课程浏览、课时播放、学习进度、个人信息和题库练习等功能。

跨领域清理和进度更新通过 Spring 事件/监听器解耦，例如删除课程、章节、课时、用户或部门时同步清理关联数据。应用启动时还会执行数据库迁移、系统数据、配置项、权限项以及考试表结构检查。

## 5. 核心业务域

- 组织与身份：学员、管理员、部门、角色、权限、登录记录、LDAP 映射与同步。
- 课程学习：课程分类、课程、章节、课时、附件、部门可见范围、学习记录和学习时长统计。
- 资源中心：资源分类、文件元数据、视频时长/封面扩展信息、普通上传与分片上传。
- 考试中心：题库、题目版本、试卷草稿与发布版本、导入导出、练习提交和自动判分。
- 系统治理：应用配置、数据迁移、权限初始化、操作日志、限流、缓存和分布式锁抽象。

## 7. 构建、测试与运行

在本目录执行：

```bash
# Windows
.\mvnw.cmd clean package

# 跳过测试构建
.\mvnw.cmd clean package -DskipTests

# 运行全部测试
.\mvnw.cmd test

# 启动应用模块
.\mvnw.cmd -pl playedu-api -am spring-boot:run
```

构建产物为 `playedu-api/target/playedu-api.jar`。启动前至少应准备可访问的 MySQL，并通过 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASS` 配置连接；生产环境必须覆盖默认的 `SA_TOKEN_JWT_SECRET_KEY`。

## 8. 开发约定与维护要点

- 新增 HTTP 能力通常在应用模块增加 Controller/Request，在对应领域模块增加 Service、Domain、Mapper 和 XML SQL。
- 管理端写操作应结合 `@BackendPermission`、`@Log`；并发敏感操作可结合 `@Lock`，其实现位于系统模块切面。
- 删除核心对象时检查是否需要发布或监听领域事件，避免课程、资源、进度等关联数据残留。
- 新增数据库结构需纳入迁移机制；考试模块当前通过启动迁移类加载模块内 SQL，其他核心表由系统模块维护。
- 当前自动化测试主要集中在应用模块的题库和试卷 HTTP 测试，修改其他领域时应补充相应单元或集成测试。

## 9. 推荐阅读顺序

1. 父工程 `pom.xml`，了解版本、模块和公共依赖。
2. `playedu-api/PlayeduApiApplication.java` 与 `application.yml`，了解启动和运行配置。
3. 应用模块的 `WebMvcConfig`、各拦截器和 Controller，理解 API 边界。
4. 根据业务进入 `playedu-common`、`playedu-course`、`playedu-resource` 或 `playedu-exam`。
5. 阅读 `playedu-system` 的启动检查和切面，掌握初始化及横切逻辑。
