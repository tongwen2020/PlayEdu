# playedu-course 课程模块概要

## 模块定位

本模块负责课程从组织、内容编排到学员学习记录的完整领域逻辑。它依赖 `playedu-common` 获取用户、部门、公共类型和基础设施，并依赖 `playedu-resource` 关联视频、音频、图文等素材。

## 核心模型

| 模型 | 用途 |
| --- | --- |
| `Course`、`CourseCategory` | 课程主数据与分类关系 |
| `CourseChapter`、`CourseHour` | 章节和课时内容编排 |
| `CourseDepartmentUser` | 课程对部门/用户的可见范围 |
| `CourseAttachment`、`CourseAttachmentDownloadLog` | 课程附件及下载审计 |
| `UserCourseRecord` | 用户的课程级进度 |
| `UserCourseHourRecord` | 用户的课时级进度与完成状态 |
| `UserLearnDurationRecord`、`UserLearnDurationStats` | 学习时长明细与统计 |
| `UserLatestLearn` | 最近学习信息投影 |

## 分层结构

- `domain`：数据库实体和查询投影。
- `mapper` 与 `resources/mapper`：基础 CRUD、课程可见性、学习统计和分页 SQL。
- `service` / `service.impl`：课程、章节、课时、附件、学习记录及统计逻辑。
- `bus/UserBus`：集中判断用户是否可见某课程。
- `caches`：用户课程可见性与最近学习时间的内存缓存。

## 主要流程

### 课程维护

管理端创建课程后，配置分类和可见部门/用户，再按“课程—章节—课时”组织内容；课时通过资源 ID 关联资源模块。附件独立排序并记录学员下载行为。

### 学习进度

学员请求课时播放信息后持续提交进度/心跳。`UserCourseHourRecordService` 更新课时记录，完成事件推动 `UserCourseRecordService` 汇总课程进度；学习时长同时写入明细并聚合到统计表。

### 可见性

`UserBus.canSeeCourse` 综合课程状态、公开范围、部门和指定用户判断访问权，结果由 `UserCanSeeCourseCache` 缓存。课程分配或组织关系发生变化时必须同步失效缓存。

## 与其他模块的边界

课程模块只维护领域逻辑，不直接暴露 HTTP；相关接口位于应用模块的课程、章节、课时、附件和用户学习 Controller。资源文件的上传、元数据和播放地址由 `playedu-resource` 负责，本模块仅保存资源关联。跨领域删除由应用模块事件监听器协调。

## 维护要点

- 删除课程、章节或课时时，检查学习记录、附件、资源引用和缓存的清理链路。
- 更新课时完成规则时，同时核对课程级进度计算和学习时长统计。
- 复杂报表查询主要位于 XML Mapper，调整字段时需同步实体、投影类型及管理端接口。
- 缓存实现为进程内缓存，多实例部署需要关注一致性。
- 本模块暂无独立测试目录，修改进度计算和可见性规则时建议补充服务层测试。
